== Rules

[[COD-500]]
*COD-500.* An executable script MUST start with `#!/usr/bin/env bash` and target Bash 4.4 or later.
A script MAY use POSIX `sh` only where its environment has no Bash, such as a minimal container image.
Check: ShellCheck, which reads the shell from the first line.

The link:https://google.github.io/styleguide/shellguide.html[Google Shell Style Guide] serves as the style guide of this page.

[[COD-501]]
*COD-501.* Each script MUST pass ShellCheck at its default severity.
It MUST pass `shfmt -d` with an indent of 2 spaces, set in `.editorconfig`.
Check: link:https://github.com/koalaman/shellcheck/releases[ShellCheck] and link:https://github.com/mvdan/sh/releases[shfmt] in {abbr-ci}.

[[COD-502]]
*COD-502.* A script MUST quote each variable and each command substitution that it expands.
It MUST pass arguments on with `"$@"`, test with `[[ ]]` and capture output with `$( )`.
It MUST NOT use `eval`.
Check: ShellCheck, and review for `eval`.

[[COD-503]]
*COD-503.* A script SHOULD start with `set -Eeuo pipefail` and `shopt -s inherit_errexit`.
It MUST still check the result of each critical command, and MUST write its errors to the standard error stream.
Check: review.

The options stop many errors, but not all of them.
The link:https://mywiki.wooledge.org/BashFAQ/105[BashFAQ entry on errexit] lists cases where a failed command does not stop the script.
A condition, a `local` assignment and some subshells are such cases.

[[COD-504]]
*COD-504.* A script MUST create temporary files and folders with `mktemp`, and remove them in a `trap` on `EXIT`.
It MUST NOT use a fixed path for temporary data.
Check: review.

[[COD-505]]
*COD-505.* A script that grows past about 100 lines MUST become a Go program, under the xref:go.adoc[Go] page.
A script that parses structured data, such as {abbr-json-first} or {abbr-xml-first}, MUST also become one.
Check: review.

The Google guide sets the same limit.
A Go program gets types, tests and the same linters as the other {abbr-fpsot-first} tools.

[[COD-506]]
*COD-506.* A script that other code depends on SHOULD have tests in link:https://github.com/bats-core/bats-core/releases[bats-core], run in {abbr-ci}.
Check: review.

Since version 1.14, `run` in bats honors `set -e`, which can break older tests.
