= JavaScript and TypeScript
include::_fpsot-terms.adoc[]

This page covers JavaScript and TypeScript, in the browser and in Node.js tools.
The front end of {abbr-fpsot-first} renders {abbr-html-first} on the server, so scripts add to pages that already work.

== Rules

[[COD-600]]
*COD-600.* New work MUST run on Node.js 26.
A project MUST run only on a line of Node.js in active or maintenance long-term support.
It MUST declare the line in the `engines` field of `package.json` and in a `.node-version` file.
Check: `npm ci` with `engine-strict=true`, which fails on a wrong engine, and review of the {abbr-ci-first} jobs.

The link:https://nodejs.org/en/about/previous-releases[Node.js releases page] lists each line and its end date.
From Node.js 27, link:https://nodejs.org/en/blog/announcements/evolving-the-nodejs-release-schedule[one major release a year] ships, and each one becomes a long-term release.

[[COD-601]]
*COD-601.* A project MUST check types and lint with TypeScript 6.0.x while typescript-eslint does not support TypeScript 7.
It MAY also compile with TypeScript 7.
Check: the version of `typescript` in the lock file, and review.

link:https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/[TypeScript 7.0] is a native port that shipped without an interface for other tools.
The link:https://typescript-eslint.io/users/dependency-versions/[supported versions of typescript-eslint] stop below TypeScript 6.1.
Rules that read types matter more than the speed of the compiler, so the linter decides.
The owner revisits this rule when typescript-eslint supports TypeScript 7.

[[COD-602]]
*COD-602.* The `tsconfig.json` file MUST turn on `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride` and `verbatimModuleSyntax`.
Code MUST use ECMAScript modules only.
Check: the compiler, and review of `tsconfig.json`.

The link:https://www.typescriptlang.org/tsconfig/[TSConfig reference] describes each option.
Code that Node.js runs without a build step also needs `erasableSyntaxOnly`.

[[COD-603]]
*COD-603.* ESLint MUST lint the code with a flat configuration and the `strictTypeChecked` set of typescript-eslint.
The ESLint comments plugin MUST turn on its rule `require-description`, under COD-010.
Prettier MUST format the code.
Check: `eslint` and `prettier --check` in {abbr-ci}.

link:https://eslint.org/docs/latest/use/migrate-to-10.0.0[ESLint 10] no longer reads the older configuration format.
The link:https://typescript-eslint.io/users/configs/[shared configurations of typescript-eslint] include `strictTypeChecked`.
link:https://prettier.io/[Prettier] owns the layout.
The file `examples/eslint.config.mjs` shows a conforming configuration.

[[COD-604]]
*COD-604.* A project MUST commit its lock file and install with `npm ci`.
Its `.npmrc` file MUST set `ignore-scripts=true`, `allow-git=none` and `engine-strict=true`.
It MUST also set `min-release-age` to at least 3 days.
Check: review of `.npmrc` and of the {abbr-ci} jobs.

These link:https://docs.npmjs.com/cli/v11/using-npm/config[npm settings] are the npm mechanism for SEC-030 and SEC-032.
TST-006 leaves the test runner open, and this page names Vitest or the `node:test` module of Node.js.
A waiting period gives the registry time to remove a malicious release before a project installs it.

[[COD-605]]
*COD-605.* A project that publishes a package to npm MUST publish it through trusted publishing, with provenance.
Check: the release workflow.

link:https://docs.npmjs.com/trusted-publishers/[Trusted publishing] uses a short-lived identity from {abbr-ci} instead of a stored token, and adds provenance on its own.
It serves SEC-024 and SEC-035.

[[COD-606]]
*COD-606.* A front end MUST render its pages as {abbr-html} on the server, and add scripts as progressive enhancement.
A project that needs a single-page application framework MUST first record that decision, with its reasons.
Check: review.

The link:https://www.gov.uk/service-manual/technology/using-progressive-enhancement[GOV.UK Service Manual] explains why pages should work before scripts load.
The default stack of {abbr-fpsot} is Qute templates with PatternFly, HTMX and Alpine.js.

[[COD-607]]
*COD-607.* Code MUST keep keyed data from outside in a `Map` or a `Set`.
It MUST NOT use a plain object as a dictionary for such data.
It MUST NOT copy keys from outside into a plain object without an allow-list.
Check: review.

This rule follows requirement 15.3.6 of the {abbr-owasp-first} {abbr-asvs-first}, which asks code to prevent prototype pollution.
