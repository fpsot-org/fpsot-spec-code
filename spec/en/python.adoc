== Rules

[[COD-900]]
*COD-900.* A service that {abbr-fpsot} ships MUST NOT run on Python.
Python MAY serve tools, checks and scripts of a build.
Check: review.

[[COD-901]]
*COD-901.* A project MUST declare `requires-python = ">=3.12"` or a later floor.
The {abbr-ci} MUST run on Python 3.14.
Check: review of `pyproject.toml` and of the {abbr-ci} jobs.

The link:https://devguide.python.org/versions/[Python versions page] shows that 3.10 reached its end of life in October 2026.

[[COD-902]]
*COD-902.* Code MUST pass `ruff check`, with the `S` security rules on, and `ruff format --check`.
It MUST pass a strict type check, with `mypy --strict` or pyright in strict mode.
Check: link:https://docs.astral.sh/ruff/rules/[Ruff] and link:https://mypy.readthedocs.io/en/stable/[mypy] in {abbr-ci}.

[[COD-903]]
*COD-903.* A project MUST lock its dependencies.
The lock MUST be `uv.lock`, inline script metadata under PEP 723, or hashes in a requirements file.
Check: review, and `uv lock --check` where `uv.lock` exists.

link:https://peps.python.org/pep-0723/[PEP 723] lets one script declare its dependencies.
link:https://docs.astral.sh/uv/concepts/projects/sync/[uv] keeps the lock file in step with the project.
This is the Python mechanism for SEC-030.

[[COD-904]]
*COD-904.* Code MUST NOT call `subprocess` with `shell=True`, `eval` or `exec` on outside data.
It MUST NOT load outside data with `pickle` or with an unsafe YAML loader.
It MUST NOT parse outside {abbr-xml-first} with a parser that resolves entities.
Check: the `S` rules of Ruff, and review.

The link:https://docs.python.org/3/library/subprocess.html[subprocess documentation] and the link:https://docs.python.org/3/library/pickle.html[pickle documentation] warn against these uses.
