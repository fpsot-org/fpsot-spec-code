= PowerShell
include::_fpsot-terms.adoc[]

This page covers PowerShell scripts and modules.
Public bodies run many Windows hosts, and {abbr-fpsot-first} needs PowerShell to install and operate software on them.

== Tools of edition 2026

[cols="2,1,3",options="header"]
|===
|Tool |Version |Role
|PowerShell |7.6 long-term support |Runs scripts on any system.
|Windows PowerShell |5.1 |Runs scripts on Windows hosts that have nothing newer.
|PSScriptAnalyzer |1.25.0 |Lints and formats scripts.
|Pester |6.2.0 |Tests scripts.
|===

The link:https://learn.microsoft.com/en-us/powershell/scripting/install/powershell-support-lifecycle?view=powershell-7.6[support lifecycle of PowerShell] gives 7.6 support until 2028-11-14.
Windows PowerShell 5.1 ships with Windows and follows its lifecycle.

== Rules

[[COD-550]]
*COD-550.* Each script and each module MUST declare the version it needs, with `#Requires -Version 5.1` or `#Requires -Version 7.6`.
The {abbr-ci-first} MUST test it on each edition that it declares.
A script for 5.1 also runs on 7.6, so the {abbr-ci} tests it on both.
Check: review of the {abbr-ci} jobs.

[[COD-551]]
*COD-551.* Each {term-repository} MUST lint its scripts with PSScriptAnalyzer and a committed settings file.
The settings MUST turn on the formatting rules, which are off by default.
They MUST also turn on `PSUseCompatibleSyntax`, with the targets `'5.1'` and `'7.0'`.
Check: `Invoke-ScriptAnalyzer` with that settings file in {abbr-ci}.

The link:https://learn.microsoft.com/en-us/powershell/utility-modules/psscriptanalyzer/rules/readme?view=ps-modules[list of PSScriptAnalyzer rules] marks which rules are off by default.
The link:https://learn.microsoft.com/en-us/powershell/utility-modules/psscriptanalyzer/using-scriptanalyzer?view=ps-modules[guide on PSScriptAnalyzer] describes the settings file.
The file `examples/PSScriptAnalyzerSettings.psd1` shows one.
The rule accepts major versions 3 to 7, so the target `'7.0'` stands for the syntax of PowerShell 7.

[[COD-552]]
*COD-552.* Scripts MUST use only approved verbs in function names, and full command names instead of aliases.
They MUST pass parameters by name.
They MUST NOT call `Invoke-Expression`, or hold a password or a key in plain text.
Check: the default rules of PSScriptAnalyzer, such as `PSUseApprovedVerbs` and `PSAvoidUsingInvokeExpression`, and review.

The link:https://learn.microsoft.com/en-us/powershell/scripting/developer/cmdlet/approved-verbs-for-windows-powershell-commands?view=powershell-7.5[list of approved verbs] comes from Microsoft.

[[COD-553]]
*COD-553.* A module MUST export its functions by explicit name, never with a wildcard.
It MUST NOT dot-source script files.
Check: the rules `PSUseConstrainedLanguageMode` and `PSUseToExportFieldsInManifest`, or review.

Under App Control for Business, PowerShell runs untrusted scripts in constrained language mode.
The link:https://learn.microsoft.com/en-us/powershell/scripting/security/app-control/how-app-control-works?view=powershell-7.5[Microsoft guide on App Control] asks modules to avoid dot-sourcing and wildcard exports.

[[COD-554]]
*COD-554.* Each released script and module MUST carry an Authenticode signature.
Install guides MUST NOT tell users to set the execution policy to `Bypass` for the whole machine.
Check: review of the release workflow and of the guides.

The link:https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-7.5[documentation of execution policies] says that the policy is no security boundary.
A signature, described in link:https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_signing?view=powershell-7.5[about_Signing], lets a host trust the script.

[[COD-555]]
*COD-555.* Each function MUST declare `[CmdletBinding()]`, which makes it an advanced function.
Code that handles an error MUST use `try` and `catch` with `-ErrorAction Stop` on the command.
A `catch` block MUST NOT be empty.
Check: PSScriptAnalyzer, with `PSAvoidUsingEmptyCatchBlock`, and review.

[[COD-556]]
*COD-556.* A script for hosts under App Control SHOULD pass the rule `PSUseConstrainedLanguageMode`.
Check: PSScriptAnalyzer with that rule turned on.

[[COD-557]]
*COD-557.* Scripts and modules SHOULD have link:https://github.com/pester/Pester/releases[Pester] tests that run in {abbr-ci} on each declared edition.
Check: review.

[[COD-558]]
*COD-558.* A script SHOULD read secrets through the SecretManagement module, never from a file in the {term-repository}.
Check: review, and the secret scan of SEC-013.

This is a SHOULD because the last release of SecretManagement dates from 2022.
The owner of this page checks its maintenance at each review.

The community guide link:https://poshcode.gitbook.io/powershell-practice-and-style[PowerShell Practice and Style] gives more advice.
Its license asks that copies share it alike, so this page only summarizes ideas from it.
