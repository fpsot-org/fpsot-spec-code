This page covers Kotlin code.
The projects of {abbr-fpsot-first} use Kotlin for some server code.
They also use it for logic that browsers or mobile apps share.
Server code in Kotlin also follows the xref:quarkus.adoc[Quarkus] page.

== Rules

[[COD-300]]
*COD-300.* Kotlin code in a Quarkus project MUST use the Kotlin version that the Quarkus platform manages.
Its beans MUST use the `all-open` compiler plugin and receive their dependencies through their constructor.
Check: review of the build file.

The link:https://quarkus.io/guides/kotlin[Quarkus guide on Kotlin] advises against another Kotlin version in a Quarkus application.

[[COD-301]]
*COD-301.* Kotlin code MUST follow the link:https://kotlinlang.org/docs/coding-conventions.html[official Kotlin coding conventions].
The link:https://github.com/pinterest/ktlint[ktlint] tool MUST check them with the code style `ktlint_official`, set in `.editorconfig`.
The link:https://detekt.dev/[detekt] tool MUST run as the static analyzer.
Check: ktlint and detekt in {abbr-ci-first}.

The latest stable release of detekt is 1.23.8.
Version 2.0 was still in alpha at the date of this review.
The next edition moves to 2.0 once it is stable.

[[COD-302]]
*COD-302.* A Kotlin library MUST turn on the explicit API mode of the compiler.
Check: the compiler, which then fails on a public declaration without an explicit visibility or type.

The link:https://kotlinlang.org/docs/api-guidelines-introduction.html[Kotlin guidelines for library authors] describe this mode.

[[COD-303]]
*COD-303.* An expected business outcome MUST be a value of a sealed type, as in Java under COD-105.
A public interface MUST NOT expose `kotlin.Result` or an `Either` type from another library for domain outcomes.
A function that Java code calls and that can throw MUST declare `@Throws`.
Check: review.

One model of errors then serves both languages of the Java platform.
The link:https://kotlinlang.org/docs/java-to-kotlin-interop.html[guide on calling Kotlin from Java] explains `@Throws`.

[[COD-304]]
*COD-304.* Code shared with a browser or a mobile app MUST live in a `commonMain` source set without framework code.
Such a module MAY build with Gradle, under COD-107.
Code that targets WebAssembly MUST stay in pilot projects while that target is in Beta.
Check: review.

The link:https://kotlinlang.org/docs/multiplatform/supported-platforms.html[stability page of Kotlin Multiplatform] lists Kotlin/Wasm as Beta.

[[COD-305]]
*COD-305.* A Kotlin interface that Java code calls SHOULD use `@JvmOverloads` and `@JvmStatic` where they help Java callers.
It SHOULD declare explicit types.
Check: review.
