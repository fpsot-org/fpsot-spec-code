== Règles

[[COD-850]]
*COD-850.* Les fichiers YAML DOIVENT réussir l’analyse de yamllint, avec une configuration versionnée.
La configuration DOIT n’accepter que `true` et `false` comme valeurs booléennes.
Elle DOIT traiter une clé répétée comme une erreur.
Vérification : link:https://yamllint.readthedocs.io/en/stable/[yamllint] en {abbr-ci-first}, avec ses règles `truthy` et `key-duplicates`.

YAML 1.1 lit des mots comme `yes` et `on` comme des valeurs booléennes.
Cela surprend les gens comme les outils.
Le fichier `examples/.yamllint.yaml` montre une configuration.

[[COD-851]]
*COD-851.* L’{abbr-ci} DOIT vérifier chaque fichier de configuration qui a un schéma publié selon ce schéma.
Vérification : link:https://check-jsonschema.readthedocs.io/en/stable/[check-jsonschema] en {abbr-ci}.

L’outil check-jsonschema comprend entre autres les schémas des flux de travail de GitHub et de Dependabot.

[[COD-852]]
*COD-852.* Chaque format de configuration que définit la {abbr-fpsot-first} DOIT fournir un schéma {abbr-json} selon la link:https://json-schema.org/draft/2020-12[version 2020-12].
Vérification : revue.

Les règles d’interface de la {abbr-fpsot} emploient la même version, selon API-023.
