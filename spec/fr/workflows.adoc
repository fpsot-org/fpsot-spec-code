= Flux de travail d’intégration continue
include::_fpsot-terms.adoc[]

Cette page vise les flux de travail de GitHub Actions.
Un flux de travail s’exécute avec les droits du {term-repository}, si bien que ses erreurs deviennent des failles de sécurité.

== Règles

[[COD-800]]
*COD-800.* Chaque flux de travail DOIT fixer `permissions` à son niveau supérieur, à `{}` ou à `contents: read`.
Une tâche qui a besoin de plus DOIT élever ses propres permissions seulement.
Vérification : l’audit `excessive-permissions` de zizmor.

Le link:https://docs.github.com/en/actions/reference/security/secure-use[guide de GitHub sur l’utilisation sécuritaire] demande le moins de permissions possible pour le jeton de chaque tâche.
C’est ainsi qu’un flux de travail respecte SEC-024.

[[COD-801]]
*COD-801.* Chaque extraction du code DOIT fixer `persist-credentials: false`.
Une étape `run` NE DOIT PAS développer une expression que contrôle une personne externe, comme `${{ github.event.issue.title }}`.
Elle DOIT plutôt passer cette valeur par une variable d’environnement.
Vérification : les audits `artipacked` et `template-injection` de zizmor.

[[COD-802]]
*COD-802.* Un flux de travail déclenché par `pull_request_target` ou `workflow_run` NE DOIT PAS extraire le code d’une demande de tirage.
Il NE DOIT PAS non plus exécuter ce code.
Vérification : l’audit `dangerous-triggers` de zizmor, et revue.

[[COD-803]]
*COD-803.* actionlint et zizmor DOIVENT s’exécuter comme vérifications requises sur chaque demande de tirage qui modifie un flux de travail.
La configuration de zizmor DOIT exiger un épinglage par empreinte pour chaque action externe, selon SEC-031.
Vérification : les vérifications requises des branches protégées.

L’outil link:https://github.com/rhysd/actionlint[actionlint] vérifie la syntaxe et exécute ShellCheck sur les étapes `run`.
Les link:https://docs.zizmor.sh/audits/[audits de zizmor] couvrent les actions non épinglées et les permissions trop larges.
Ils couvrent aussi les déclencheurs dangereux et l’injection par gabarit.
Les fichiers `examples/zizmor.yml` et `examples/workflow-lint.yml` montrent une configuration.

[[COD-804]]
*COD-804.* Un projet DOIT construire les artefacts de ses versions dans un flux de travail réutilisable.
Ce flux de travail DOIT attester la provenance de chaque artefact et de sa nomenclature logicielle.
Vérification : revue du flux de travail de publication.

Les link:https://docs.github.com/en/actions/concepts/security/artifact-attestations[attestations d’artefacts de GitHub] donnent le niveau de construction 2 de SLSA, qu’exige SEC-035.
Dans un flux de travail réutilisable, elles donnent le niveau 3.

[[COD-805]]
*COD-805.* Chaque tâche qui exécute des étapes DOIT fixer `timeout-minutes`.
Chaque flux de travail qui déploie ou publie DOIT fixer `concurrency`.
Vérification : revue.

[[COD-806]]
*COD-806.* Un projet DEVRAIT exécuter OpenSSF Scorecard et publier son résultat.
Vérification : le flux de travail link:https://github.com/ossf/scorecard[Scorecard].

== Fichiers de verrouillage des flux de travail

GitHub a annoncé les fichiers de verrouillage des flux de travail en préversion publique le link:https://github.blog/changelog/2026-10-14-github-actions-workflow-lockfiles-in-public-preview/[2026-10-14].
Un tel fichier peut remplacer l’épinglage par empreinte.
Les comptes rendus sur leur disponibilité générale se contredisent, et les forfaits visés restent flous.
L’épinglage par empreinte selon SEC-031 demeure la règle.
Une édition ultérieure passera aux fichiers de verrouillage quand ils seront offerts à tous sur les forfaits gratuit et Team.
