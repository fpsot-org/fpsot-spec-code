= HTML et CSS
include::_fpsot-terms.adoc[]

Cette page vise les gabarits qui produisent du {abbr-html-first}, ainsi que les feuilles de style.
La spécification sur l’accessibilité fixe ce que les pages doivent offrir aux personnes, à partir d’ACC-001.
La spécification sur le style fixe les jetons de design et les thèmes, à partir de STY-001.
Cette page ajoute les règles mécaniques.

== Règles

[[COD-650]]
*COD-650.* L’{abbr-ci-first} DOIT vérifier les pages produites avec le Nu HTML Checker, et échouer sur une erreur.
Vérification : le link:https://validator.github.io/validator/[Nu HTML Checker] dans l’{abbr-ci}.

Un gabarit n’est pas encore du {abbr-html}.
La vérification lit donc les pages que l’application produit pendant ses tests.

[[COD-651]]
*COD-651.* Les gabarits NE DOIVENT PAS contenir de scripts en ligne, d’attributs `style` ni d’attributs qui gèrent des événements.
Les scripts DOIVENT fonctionner sous une politique de sécurité du contenu sans `'unsafe-inline'` ni `'unsafe-eval'`.
Une bibliothèque de scripts qui compile des expressions à l’exécution DOIT alors employer sa version prévue pour les politiques strictes.
Vérification : un test qui charge chaque page sous cette politique, et la revue.

La link:https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Security-Policy/script-src[page de MDN sur script-src] explique comment ces mots clés affaiblissent la politique.

[[COD-652]]
*COD-652.* Un gabarit Qute NE DOIT PAS afficher sans échappement des données qu’une personne a fournies.
Il NE DOIT PAS appliquer `raw` ou `safe` à de telles données.
Vérification : une recherche de `raw` et de `safe` dans les gabarits par l’{abbr-ci}, et la revue de chaque résultat.

Le link:https://quarkus.io/guides/qute-reference[guide de référence de Qute] échappe la sortie par défaut dans les gabarits {abbr-html}.

[[COD-653]]
*COD-653.* Les feuilles de style DOIVENT passer stylelint avec `stylelint-config-standard`.
Elles DOIVENT prendre les couleurs, les espacements et la typographie dans les propriétés personnalisées du système de design, selon STY-001.
Vérification : link:https://stylelint.io/[stylelint] dans l’{abbr-ci}, avec `color-no-hex` et `color-named` pour les couleurs brutes.
Le plugiciel link:https://github.com/AndyOGo/stylelint-declaration-strict-value[stylelint-declaration-strict-value] vérifie les espacements et la typographie, et la revue couvre le reste.

[[COD-654]]
*COD-654.* Les feuilles de style DEVRAIENT ordonner leurs couches avec `@layer`, à la manière de CUBE CSS.
Les blocs que rédige la {abbr-fpsot-first} DEVRAIENT nommer leurs classes à la manière de BEM.
Un projet DEVRAIT employer les composants et les jetons de PatternFly avant d’écrire les siens.
Vérification : revue.

link:https://cube.fyi/[CUBE CSS] et link:https://github.com/getbem/getbem.com[BEM] vont bien ensemble.
CUBE ordonne les couches, et BEM nomme les blocs qu’elles contiennent.
