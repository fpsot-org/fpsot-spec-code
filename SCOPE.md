# Scope

This Working Group develops the FPSOT code specification.

The specification covers how FPSOT projects and their adopters write, format, check and build software: the choice and pinning of one formatter and one linter set per language, enforced in continuous integration; prose rules for what tools cannot check; suppressions of findings and generated code; license headers and EditorConfig; declared toolchains and one-command builds; style editions and the review of each language page; names inside source code; the names of release files and reproducible builds; and language pages for Java, Quarkus, Kotlin, Go, Bash, PowerShell, JavaScript and TypeScript, HTML and CSS, SQL and database migrations, container files, CI workflows, configuration files and Python tooling. It includes example configuration files and the scripts that check them.

It does not cover the outcomes that other FPSOT specifications set, such as static analysis gates, secrets and the supply chain (security), commits and releases (version control), tests (testing), published names (naming) and log records (observability); how an adopter replaces a part and which part wins, published bills of materials and product assembly, which a future FPSOT specification on capabilities will cover; allowed licenses and copyright notices, which a future legal specification will cover; or the prose of specifications, which the writing specification covers.

Any changes of Scope are not retroactive.
